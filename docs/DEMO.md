# SParamKit 演示讲稿

适用版本：0.1.0。建议用五分钟完成展示，演示前将交付包完整解压到本地。

## 1. 项目介绍（约 30 秒）

SParamKit 是一个用 MoonBit 编写的 Touchstone 数据工具。我希望把射频文件的读取、检查和常用分析整合到一个可离线使用的工具里，同时把核心库提供给其他 MoonBit 项目复用。

项目支持一端口和二端口 S 参数文件。浏览器工作台和命令行共用同一套 MoonBit 解析、转换和导出逻辑。

## 2. 曲线与逐点读数（约 60 秒）

打开交付包根目录的 `index.html`，点击“打开离线工作台”。默认显示双端口陷波电路的 291 个频点。切换 S21 / S11，再切换线性与对数频率轴。

在曲线上选择一个频点，使用滑块或方向键移动，展示该点的频率、实部、虚部、幅度、分贝和相位。切换参数后，选中的频点仍保持不变，便于对照。

这里显示的是文件中的原始采样点；内置电路是合成演示数据。

## 3. 文件导入与导出（约 60 秒）

准备一份 UTF-8 文本，保存为 `demo.s2p`，然后通过文件选择器导入：

```text
# MHz S RI R 75
100 0.1 0 0.3 -0.4 0.2 0 0.1 0
200 0.2 0 0.4 -0.3 0.1 0 0.2 0
```

顶部应显示两个频点、100–200 MHz 和 75 Ω。第一个频点的 S21 为 `0.3 - 0.4i`，幅度为 `0.5`，分贝约为 `-6.0206 dB`，相位约为 `-53.1301°`；S12 则为 `0.2 + 0i`。这组非对称数据可以检查 S21 / S12 是否读取正确。

分别导出 CSV 和 JSON。CSV 有一行表头和八行参数数据；JSON 保留两个频点的全部四个 S 参数。界面选中的参数和分页不会截断导出结果。

## 4. 错误处理（约 60 秒）

将任意数值替换为 `abc` 后重新解析。页面会显示错误原因和行列位置，点击“定位错误”会选中对应字段。此时旧曲线已经清除，导出按钮不可用。

重新导入同一份正常文件即可恢复。再展示页面内置的错误样例，说明不完整记录同样会被拒绝。

## 5. 核心库与验证（约 90 秒）

展示源码中的 `parse_touchstone`、`Network::get_s` 和导出接口，然后打开 `source/docs/LIBRARY.md`，说明如何在独立 MoonBit 工作区接入。

打开 `reports/`：核心测试分别在 JS 和 wasm-gc 上执行；独立数值对照检查频率、复数值和导出结果；源码包会在新目录解压重建。演示首页可直接进入对应报告。

收尾说明：这次交付专注于一端口、二端口文件的“导入—检查—曲线—导出”，不扩展到仪器控制或完整射频仿真。

## 技术问题速查

**为什么二端口数据不是 S11、S12、S21、S22？**

当前支持的 Touchstone 二端口文件按 S11、S21、S12、S22 排列。API 的 `get_s(样本索引, 输出端口, 输入端口)` 按 Sij 定义查询，所以 `get_s(0, 2, 1)` 是第一个频点的 S21。

**RI、MA、DB 怎样转换？**

RI 直接给出实部和虚部；MA 给出幅度和以度为单位的相位；DB 的幅度先通过 `10^(dB/20)` 还原，再按相位计算实部与虚部。频率在核心数据模型中统一为 Hz。

**“归一化”会把 75 Ω 变成 50 Ω 吗？**

不会。这里统一的是频率单位和复数表示。文件头的正实数参考阻抗被保留；已识别的端口阻抗声明与文件头冲突时会报错。

**零幅度为什么不显示 0 dB？**

零幅度没有有限分贝值，相位也未定义。因此界面显示空缺，JSON 写为 `null`。0 dB 对应幅度 1，不能用来代替零幅度。

**MoonBit 实际负责什么？**

词法和格式解析、数据模型、数值转换、诊断、查询以及 CSV / JSON 报告。浏览器的 JavaScript 负责文件交互与绘图；Node.js 负责命令行文件读写。Python 和 scikit-rf 用于构建或测试。

**怎样复现验证？**

在源码目录按 [验收指南](ACCEPTANCE.md) 安装依赖，执行 `python tools/prepare_submission.py`。完整流程通过后会生成带本次日志和报告的交付包。

**当前支持到哪里？**

Touchstone 1.x 的一端口、二端口 S 参数子集，工作台和 CLI 的 UTF-8 文件上限为 2 MiB、20,000 个频点。详细输入规则和厂商扩展处理见 [兼容性说明](COMPATIBILITY.md)。

代码结构与设计取舍见 [架构设计](ARCHITECTURE.md)。
